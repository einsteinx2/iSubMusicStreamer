## Release-readiness summary

The port is functionally roughed-in across most tabs but is not shippable. Two systemic problems dominate: there is no automatic data or cache migration, so every existing user would lose their servers, credentials, playlists, downloads, bookmarks, and settings on upgrade; and the repository contains zero automated tests of any kind (no XCTest or XCUITest target exists at all). Layered on top are concrete parity regressions — entire browsing surfaces (Genres, All Albums, All Songs) are missing, playlist/bookmark mutation is largely stubbed, and the streaming buffer-underrun loop is a no-op — plus scattered crash-level and correctness bugs. ## Recommended execution order

1. **Test infrastructure + fixtures** — Nothing else can be verified without it; stand up unit/integration/UI-test targets, a mock Subsonic server, fixture XML/JSON, a temp DB+cache sandbox, and a Resolver test container, since every subsequent coverage item depends on this foundation.
2. **Data & cache migration (old -> new)** — This is the P0 data-loss release blocker, so implement and test the FMDB-to-GRDB data migration and the flat-to-nested media-cache migration (with versioning, partial-failure handling, and off-main-thread execution) before shipping anything.
3. **Core playback & parity blockers** — Fix the ship-blocking defects that a user hits immediately: the buffer-underrun no-op that breaks streaming, the RepeatMode plist crash, the broken shuffle notification, and the malformed store/download-queue SQL, so the app is stable end-to-end.
4. **Remaining feature parity** — Restore the visible App Store regressions: the missing Genres, All Albums, and All Songs browsing surfaces, playlist and bookmark mutation, Play-All/Shuffle in Downloads, and the dropped settings and empty-state UI.
5. **Full test coverage** — With features complete and the harness in place, backfill comprehensive unit, integration, and XCUITest suites against the manual integration spec (including iPad, video, and audio-session flows) to earn upgrade confidence.
6. **Build, CI & cleanup** — Finish the shipping plumbing: add a shared App Store scheme, wire CI to run the new test targets, remove dead files, and resolve dependency-pin and minimum-iOS decisions.
